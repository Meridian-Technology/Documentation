## Machine-local profiles contract

The checked-in example documents the shape; the real file lives under `RELAY_DATA` and is not committed:

```json
{
  "expo": {
    "cwd": "Meridian-Mobile",
    "command": "/absolute/path/to/npm",
    "args": ["run", "start:justgo"],
    "url": "REPLACE_ON_MINI"
  },
  "web": {
    "cwd": "Meridian/frontend",
    "command": "/absolute/path/to/npm",
    "args": ["start"],
    "url": "REPLACE_ON_MINI"
  }
}
```

Rules:

- `expo` and `web` are optional; selecting an unconfigured profile returns a structured error.
- `command` must be absolute in the real Mini file. Tests may use `process.execPath`.
- `args` is an array, not a shell string.
- `cwd` must stay beneath `RELAY_WORKSPACE` after resolution.
- `url` is operator configuration returned as `previewUrl`; Relay does not guess a public URL.
- The supervisor injects `REACT_NATIVE_PACKAGER_HOSTNAME` for `expo` from a Mini-only environment value. It does not commit the IP.
- Profile logs must not echo the full environment.

## Lifecycle contract

| Event | Required behavior |
| --- | --- |
| Kickoff `preview: none` | Reconcile/stop an older preview; run as profile `agent` |
| Kickoff `preview: expo` | After VC alignment, start configured Expo process; save URL; profile `agent+expo` |
| Kickoff `preview: web` | After VC alignment, start configured web process; save URL; profile `agent+web` |
| Awaiting approval | Keep selected preview alive |
| `POST preview` switch | Stop old child, start requested child, then persist preview and URL; if startup fails, restore the previous profile when possible or report `agent`, but never report the failed new profile |
| Run `done` | Keep preview for review; release run mutex normally |
| Run `failed` | Tear preview down and report `agent` |
| `POST stop` | Abort adapter, tear preview down, persist failed run |
| Next kickoff | Tear down any preview retained by a prior completed run before starting the new selection |
| API SIGTERM/SIGINT | Gracefully stop owned child before process exit |
| API restart | Read supervisor metadata, verify ownership safely, remove stale state, and restart only the active parked run's selected profile |

Do not use PID existence alone to kill a process after restart. Persist enough identity to avoid signaling an unrelated process that reused the PID; if ownership cannot be established, fail safe and require the operator to reconcile it during Phase 3.

Work phases **in order**. Each phase lists what ships and how you know it’s done.

## What we’re fixing

The crew UI on Week was layered onto the solo swipe flow. Chips, banners, cards, sheets, and recap blocks compete instead of telling one story.

**North star:** one Week tab, one weekly arc:

```text
drop      → every crew visible, same weight
swipe     → your deck feeds your crews
decide    → Week hub triage → per-crew room (multi-open; see decide UI rewrite)
recap     → where you’re going first, your picks always below
```

## Release model — paired ship, safe cutover

We ship the **new store binary** and **backend** together once App Review passes — but we do **not** hard-break users on older builds during store rollout.

Two mechanisms work together:

### 1. Old paths stay until we remove them

**Current binary** keeps using today’s routes unchanged:

- `GET /pivot/feed`
- `GET /pivot/crews/week`
- `GET /pivot/crews/:crewId/week/judgement`
- `GET /pivot/week-recap` (current response shape)
- Existing confirm / swap POSTs

**New binary** uses ritual routes only on Week:

- `GET /pivot/week-ritual`
- `GET /pivot/crews/week/judgements`
- Recap embedded in ritual (or a `/v2` recap if split later)

Mark old Week crew paths **`@deprecated — remove after min store version`** in code and docs. Delete when install base on the old binary is negligible.

**Do not** reshape `GET /pivot/week-recap` in place — that breaks the old app. New recap shape lives in ritual (preferred) or a versioned route.

Shared routes (feed, confirm, swap) keep stable contracts across both binaries.

### 2. New routes require the new store version

Every mobile request sends **`X-App-Version`** (from `expoConfig.version`).

Middleware on **new routes only**:

```text
if missing or below ritualMinAppVersion → 426
{ code: 'APP_UPGRADE_REQUIRED', minAppVersion: '2.0.0' }
```

Old binary never calls these routes → unaffected.

### 3. Update gate — get people onto the new binary

**On launch (primary):** extend `GET /pivot/config` with a `mobile` block:

```json
{
  "mobile": {
    "minAppVersion": "2.0.0",
    "forceUpdate": true,
    "storeUrls": {
      "ios": "https://apps.apple.com/app/idXXXXXXXX",
      "android": "market://details?id=com.meridian.mobile"
    },
    "message": "update to keep going with your crew this week"
  }
}
```

If `currentVersion < minAppVersion` and `forceUpdate: true`:

- Full-screen gate — no dismiss, no Week tab behind it
- Single action opens App Store / Play
- Skip in `__DEV__` or internal builds as needed

**On API use (backup):** global handler for `426` + `APP_UPGRADE_REQUIRED` shows the same gate (covers stale config or sideloaded old builds hitting ritual routes).

**Timing:** deploy backend with `minAppVersion` **below** live store version first; bump to the new version **only after** the store build is searchable. Otherwise users see “update required” with nothing to install.

**OTA note:** `expo-updates` only applies within the same store version (`runtimeVersion: appVersion`). The ritual release is a **store update**, not an OTA push.

### Release sequence

```text
1. Backend: new ritual routes (gated) + config.mobile block (min below current)
2. Submit new binary (ritual UI + X-App-Version + update gate)
3. App approved → release to stores
4. Backend: set minAppVersion to new store version, forceUpdate: true
5. Monitor crew KPIs + crash on Week
6. Later: remove deprecated Week paths + old mobile UI
```

## Ritual payload (sketch)

`GET /pivot/week-ritual?batchWeek=` returns:

```typescript
{
  batchWeek: string;
  phase: 'solo' | 'pre_drop' | 'drop_live' | 'swiping' | 'decide' | 'recap';
  drop: { /* schedule */ };
  deck: { remaining, complete, holdUntil };
  crews: Array<{
    crewId, name,
    swipeProgress: { swiped, active, quorumMet, members: [...] };
    judgement: { status, proposed, runnerUp, needsUserAction, ... };
  }>;
  recap?: { crewOutcomes, personal };
  nudge?: { type, crewId?, copyKey };
  actions: { openDeck, openDecide, openRecap };
}
```

Server owns **`phase`** and **`decideQueueOrder`** — the client renders, it doesn’t guess.

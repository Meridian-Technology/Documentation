The corrected path gives every user a personal link that never dies, says who invited you, picks the city for you, and makes you friends when you join. App screens stay in the conventional register; the web landing page uses the loud cut-paper register.

system

 inviter (signed in, any city)                  invitee
 ─────────────────────────────                  ───────
 GET  /pivot/invites/me ──► PivotUserInvite     taps justgo.lol/invite/{code}
      (lazily created;       {code, globalUserId,     │
       one per user+city)     tenantKey, tenantUserId, ├─ app installed ─► usePivotInviteDeepLinkBoot
                              inviterName/Picture,     │                    GET /pivot/invites/{code}/preview  (public)
                              acceptedCount}           │                    signed out: set inviter's city, store pending
 share sheet: justgo.lol/invite/{code}                 │                    signed in, same city: confirm sheet
                                                       │                    signed in, other city: info toast
                                                       └─ no app ───────► web /invite/:code  (who + city + store + "open in just go")

 after sign-in ─► PivotInviteAcceptSync ─► POST /pivot/invites/{code}/accept
                    • Friendship(inviter ⇄ invitee, accepted)   (skips if blocked, self, or another city)
                    • PivotUserInviteAcceptance {code, inviter, invitee, friended}   (idempotent per invitee+code)
                    • acceptedCount += 1
                    • push to inviter: pivot_invite_accepted → PivotFriends
                    • growth dashboard counts the invitee as "referred"

 Admin cohort codes (PivotReferralCode) stay as campaign attribution. They are never a gate, and an
 expired or maxed code now drops silently into normal open entry.
